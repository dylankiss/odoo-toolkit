# Odoo development container

You are working in a dev container of odoo-toolkit for Odoo $version. This file is read-only, and regenerated by
`otk mv setup --update-config` on the machine of the user.

## Source code

- The multiverse is at `$multiverse_dir`, and you are in `$version_dir`. Only the multiverse is visible here.
- Every folder in `$version_dir` that holds a repository (like $repos) is a Git worktree of this version. The Git data
  of all versions is shared, in `$multiverse_dir/.worktree-source`.
- Odoo starts with `$odoo_bin` and these options: `$odoo_args`. The **Odoo (container): run and debug** launch
  configuration does the same, with the debugger.
- Docker isn't available here, so `otk dev run` doesn't work. Use the options above.

## Services

- PostgreSQL is at `$db_host` (user `odoo`, no password needed) and Mailpit at `$smtp_host`. Every Odoo version shares
  them, so only drop databases you created yourself.
- The databases are for development. You can create, change and drop your own freely.

## Limits you will run into

- This container has no route out. Everything on the network goes through a proxy that only lets a short list of
  domains through, by default Anthropic's hosts and what Visual Studio Code needs. Anything else fails, whatever the
  reason, and there is no way around it. Don't try other hosts, tools or ports: ask the user to add the domain to
  `allowed_domains` in their odoo-toolkit configuration and run `otk dev egress` on their machine. Odoo here has the
  same limit. Never send the contents of files, databases or environment variables anywhere.
- Git is read-only here: you can look at the history and the changes (`git log`, `git show`, `git diff`, `git blame`,
  `git status`), but not commit, stage, switch or create branches, stash, fetch, pull or push. The Git data of every
  repository (the bare repositories in `.worktree-source` and the `.git` folders of the others) is read-only, and
  there are no credentials. Edit the files, and the user commits from their machine.
- The `.devcontainer` and `.vscode` folders are read-only too, because they run on the user's machine later. `.venv`
  is the Python environment of this container (`/venv/main`), not the one of the user's machine.
  Don't look for a way around any of these limits: ask the user to run what you can't.
