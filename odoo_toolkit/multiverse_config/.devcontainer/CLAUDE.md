# Odoo development container

You are working in a dev container of odoo-toolkit for Odoo $version. This file is read-only, and regenerated by
`otk mv setup --update-config` on the machine of the user.

## Source code

- The multiverse is at `$multiverse_dir`, and you are in `$version_dir`. Only the multiverse is visible here.
- Every folder in `$version_dir` that holds a repository (like $repos) is a Git worktree of this version. The Git data
  of all versions is shared, in `$multiverse_dir/.worktree-source`.
- Odoo starts with `$odoo_bin` and these options: `$odoo_args`. The **Odoo (container): run and debug** launch
  configuration does the same, with the debugger.
- Docker isn't available here, so `otk dev run` doesn't work. Use the options above.

## Services

- PostgreSQL is at `$db_host` (user `odoo`, no password needed) and Mailpit at `$smtp_host`. Every Odoo version shares
  them, so only drop databases you created yourself.
- The databases are for development. You can create, change and drop your own freely.

## Limits you will run into

- The network is open, like on the machine of the user. Ask the user before you fetch an external site or send anything
  to one, whatever the reason, and never send the contents of files, databases or environment variables.
- Git has no credentials here: fetching, pulling and pushing don't work. Commits do. The user pushes from their machine.
- The `config` file and `hooks` folder of every repository in `.worktree-source`, and the `.devcontainer`, `.vscode` and
  `.venv` folders, are read-only, because they run on the user's machine later. Commands like `git config`,
  `git remote add` and a branch that tracks a remote fail. Ask the user to run them, and don't look for a way around it.
